These commands accept the [global flags](/reference/global-flags/).

## `bb auth login`

```bash
bb auth login [options]
```

In an interactive terminal, choose OAuth or an API token. Outside a terminal,
login defaults to OAuth unless token flags or `BB_API_TOKEN` select API-token
authentication.

The `--username` flag, `BB_USERNAME` variable, and stored `username` key keep
their existing names for compatibility.

### Options

| Option                           | Description                                                |
| -------------------------------- | ---------------------------------------------------------- |
| `-u, --username <username>`      | Atlassian account email for API tokens; selects token auth |
| `-p, --password <password>`      | API token; selects token auth                              |
| `--with-token`                   | Read and trim the token from stdin; selects token auth     |
| `--app-password`                 | Legacy flag name for API-token auth                        |
| `--client-id <clientId>`         | Custom OAuth consumer key                                  |
| `--client-secret <clientSecret>` | Custom OAuth consumer secret                               |

`BB_USERNAME` supplies the email when `-u` is absent; `BB_API_TOKEN` supplies
the token when `-p` or `--with-token` is absent. The mere presence of
`BB_API_TOKEN`, even empty, selects token auth. See [Environment
variables](/reference/environment-variables/#resolution-order).

### Examples

```bash
bb auth login
printf '%s' "$BB_API_TOKEN" | bb auth login -u you@example.com --with-token
bb auth login --client-id YOUR_KEY --client-secret YOUR_SECRET
```

The flag retains its historical name, but [Atlassian requires your account
email for API tokens](https://support.atlassian.com/bitbucket-cloud/kb/getting-401-http-error-while-authenticating-to-bitbucket-cloud-rest-apis/).
Avoid literal secrets in arguments or shell history.

### How it works

In a terminal, token login asks for any missing email or token. Prompts are
disabled for pipes, redirected output, `--json`, `--no-input`, or
`BB_PROMPT_DISABLED`. Empty stdin with `--with-token` fails with `5001`;
combining `--with-token` and `-p` fails with `5002`.

OAuth opens a browser and waits for a callback at
`http://localhost:19872/callback`. There is no device-code flow. Normal token
expiry is refreshed automatically; revoked or invalid refresh credentials
require another login.

API-token login stores the credentials, verifies them against `GET /user`,
and clears them if verification fails. A failed login can replace and clear
previous credentials, so it is not a harmless validation of a second account.

`--app-password` selects API-token auth; it does not restore support for
Bitbucket app passwords.

### Required scopes (API token)

Login and status need `read:user:bitbucket`. Include the scopes for your other
commands as well. OAuth grants come from the consumer's permissions; a custom
consumer can grant more than the CLI's requested scope list. See
[Token scopes](/reference/token-scopes/).

## `bb auth logout`

```bash
bb auth logout [options]
```

### Examples

```bash
bb auth logout
bb auth logout --json
```

### What gets removed

Logout clears credentials for the active authentication method. OAuth logout
also removes custom consumer credentials. It attempts OAuth revocation first and preserves settings such
as `defaultWorkspace` and aliases. If revocation fails, local credentials are
still cleared and JSON includes `revokeFailed: true`.

## `bb auth status`

```bash
bb auth status [options]
```

### Examples

```bash
bb auth status
bb auth status --json
```

### Output

```text
✓ Logged in to Bitbucket
  Authentication: API Token
  Username: myuser
  Display name: My Name
  Account ID: 712020:3cfed7e0-0ed6-49fc-bb35-410a00ccee6f
  Default workspace: myworkspace
```

The displayed username comes from Bitbucket, even when login used an email.
OAuth adds a token-expiry line. The default workspace appears only when set.
With no credentials, the command reports `Not logged in` and JSON is
`{ "authenticated": false }`.

`auth status --json` and `auth login --json` both report `method` as
`"api_token"` or `"oauth"`. Earlier releases reported `"basic"` from
`auth status` for API tokens. See [JSON
output](/reference/json-output/#pattern-5-auth--config-custom).

## `bb auth token`

```bash
bb auth token [options]
```

### Examples

```bash
bb auth token
bb auth token | pbcopy  # macOS clipboard
bb auth token --json
```

### Output

| Login method | Text output                                            | JSON type |
| ------------ | ------------------------------------------------------ | --------- |
| OAuth        | Bearer access token, refreshed if needed               | `bearer`  |
| API token    | Base64 of the stored email and token, separated by `:` | `basic`   |

For an existing OAuth login:

```bash
curl -H "Authorization: Bearer $(bb auth token)" https://api.bitbucket.org/2.0/user
```

For an API-token login:

```bash
curl -H "Authorization: Basic $(bb auth token)" https://api.bitbucket.org/2.0/user
```

This command deliberately reveals credentials. Base64 is reversible, not
redaction. Keep its output out of logs, issue reports, and agent prompts.
