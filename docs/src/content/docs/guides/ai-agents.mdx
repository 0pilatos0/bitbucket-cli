Drop a skill or rules file into your project and your coding assistant drives Bitbucket through `bb`. The templates below cover Claude Code, opencode, Cursor, and Windsurf.

## Quick start

Install `bb` and authenticate yourself first. A [standalone binary](/getting-started/installation/#standalone-binary) needs no runtime; the npm package requires Bun 1.1.30 or newer, and Windows `--jq` requires Bun 1.4.2 or newer.

```bash
bb auth login
bb auth status
```

Ask your assistant to run `bb --help`, then `bb pr list --all --json`.
For repeated use, put these instructions in its project rules or skill file:

```markdown
## Bitbucket CLI

Use `bb` for Bitbucket Cloud operations.

- Run `bb --help` and `bb <group> <command> --help` before using unfamiliar flags.
- Use `--json` after the command for structured output. Use `--all` on list
  commands that support it when the task needs every result. Add `--lean` to
  drop link noise, or `--jq <filter> --raw-output` to get plain strings.
- Workspace and repository come from the origin remote. Pass -w and -r
  explicitly when operating outside that checkout.
- Read PRs with `bb pr view <id>`, `bb pr diff <id>`, and
  `bb pr comments list <id> --all --unresolved`.
- `bb pr checks <id>` reads one page of build statuses. For automation,
  use the documented paginated API recipe rather than treating it as complete.
- Use `bb api <endpoint>` for operations without a typed command.
- Follow the user's approval rules before posting comments, approving,
  pushing, merging, or deleting resources.
- Add `--dry-run` to a write command to show the exact request (method, URL,
  body) without sending it.
- Never read, print, or copy credentials. Ask the user to authenticate.
  Without a terminal, `bb auth login` fails with code 1001 instead of opening
  a browser.
```

## Example workflows

### Create and submit a PR

After the user authorizes a push and PR creation:

```bash
git push -u origin feat/input-validation
bb pr create -t "Add input validation" -b "Validates email and password fields." --draft
```

### Review multiple PRs at once

```bash
bb pr list --all --json
bb pr view 42 --json
bb pr diff 42
bb pr comments list 42 --all --unresolved --json
```

The list and diff do not prove merge readiness. Inspect approvals and required
checks, and follow the repository's merge policy.

### Full review-and-merge cycle

Review the changes and run the relevant tests before requesting approval to
merge. For unattended merge logic, use the
[CI checks recipe](/recipes/auto-merge-on-ci-green/).

```bash
bb pr checkout 42
bb pr diff 42
# After the user authorizes approval and merge:
bb pr approve 42
bb pr merge 42 --strategy squash --close-source-branch
```

### Work an open review thread

Read unresolved threads, fix the code, then post and resolve only when authorized:

```bash
bb pr comments list 45 --all --unresolved
bb pr comments reply 45 109820 "Capped retries at 3 attempts in a1b2c3d."
bb pr comments resolve 45 109820
```

For multi-line markdown, pass the text on stdin with `-F -` and a quoted
heredoc, so backticks and `$` reach Bitbucket as written. The same flag works on
`bb pr create`, `bb pr edit` and `bb pr comments add`:

```bash
bb pr comments reply 45 109820 -F - <<'EOF'
Capped retries at 3 attempts in `a1b2c3d`.
EOF
```

### Draft PR workflow

```bash
bb pr create -t "WIP: New dashboard" --draft
bb pr ready 48
bb pr reviewers add 48 '{alice-uuid}'
```

## Security

<Aside type="caution">
  Never commit API tokens to version control. Use environment variables or `bb
  auth login`.
</Aside>

Normal `bb` commands use stored credentials internally, so the assistant does
not need a token in its prompt. This is not a security boundary: an agent with
file or shell access can read the config (plaintext unless
`credentialStorage` is `keychain`) or run `bb auth token`.
Use your assistant's tool permissions to control that access. Rule and skill
files provide instructions, not credential isolation.

For CI/CD or shared environments, use environment variables:

```bash
export BB_USERNAME="you@example.com"
export BB_API_TOKEN="your-api-token"
bb auth login   # BB_USERNAME contains your Atlassian account email
```

### Required API token scopes

Choose scopes for the operations your agent needs, using the
[command-to-scope reference](/reference/token-scopes/). Read-only access still
requires the appropriate read scope for each resource.

### OAuth agents

The CLI requests `account repository repository:admin pullrequest pullrequest:write`.
The OAuth consumer's configured scopes determine the resulting grant; this
request does not narrow a consumer configured with more scopes.

For commands outside repository and PR work, use an API token with the required
scopes or configure a custom consumer with those scopes. See
[Authentication](/getting-started/authentication/#using-a-custom-oauth-consumer) and
[Atlassian's OAuth scope rules](https://support.atlassian.com/bitbucket-cloud/docs/use-oauth-on-bitbucket-cloud/).

## Troubleshooting

| Issue                         | Solution                                                                                                                        |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| "Not authenticated"           | Run `bb auth login`; for tokens, set `BB_USERNAME` to your account email and `BB_API_TOKEN` before login                        |
| "Browser login needs an interactive terminal" | The agent has no terminal, so OAuth can't finish. Set `BB_USERNAME` and `BB_API_TOKEN`, or run `bb auth login` yourself |
| Claude doesn't use `bb`       | Restart Claude Code after creating the skill file. Check `/bb-cli` shows in the slash menu                                      |
| "Could not determine repo"    | Run from a git repo with a Bitbucket remote, or pass `-w`/`-r` flags explicitly                                                 |
| Skill not auto-activating     | Invoke manually with `/bb-cli`, or check the `description` field in SKILL.md                                                    |
| Cursor rule not loading       | Ensure the file is at `.cursor/rules/bb-cli.mdc` with valid frontmatter. Restart Cursor                                         |
| opencode ignoring AGENTS.md   | Ensure the file is in the project root (not a subdirectory). Restart opencode                                                   |
| `bb` command not found        | Install with `npm install -g @pilatos/bitbucket-cli`. The npm package requires Bun 1.1.30+; standalone binaries need no runtime |
| AI using wrong flags          | Tell the AI to run `bb <command> --help` first                                                                                  |
| Windsurf not picking up rules | Ensure the shared instructions are in the root `AGENTS.md`                                                                      |

## `llms.txt` for IDE agents

The docs site publishes the [`llms.txt`](https://llmstxt.org/) convention so
agents that fetch documentation on demand (Cursor, Cline, Continue, Aider,
and similar) can pull a clean markdown view of the full reference instead
of scraping HTML:

| URL                                                                                                         | Contents                                                                    |
| ----------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| [`/llms.txt`](https://bitbucket-cli.paulvanderlei.com/llms.txt)                                             | Index of every page with a one-line description, plus the sets below        |
| [`/<page>.md`](https://bitbucket-cli.paulvanderlei.com/commands/pr.md)                                      | Any single page as markdown: add `.md` to its path, e.g. `/commands/pr.md`  |
| [`/_llms-txt/pull-requests.txt`](https://bitbucket-cli.paulvanderlei.com/_llms-txt/pull-requests.txt)       | Topic set: every `pr` page plus the reviewer and auto-merge recipes         |
| [`/_llms-txt/pipelines-and-ci.txt`](https://bitbucket-cli.paulvanderlei.com/_llms-txt/pipelines-and-ci.txt) | Topic set: pipelines, deployments, commit statuses and CI/CD setup          |
| [`/_llms-txt/scripting.txt`](https://bitbucket-cli.paulvanderlei.com/_llms-txt/scripting.txt)               | Topic set: JSON output, error codes, environment variables and scripting    |
| [`/llms-full.txt`](https://bitbucket-cli.paulvanderlei.com/llms-full.txt)                                   | Every doc page concatenated as markdown                                     |
| [`/llms-small.txt`](https://bitbucket-cli.paulvanderlei.com/llms-small.txt)                                 | Abridged subset (excludes Help / FAQ / Changelog) for tight context windows |

Start an agent at `/llms.txt` so it fetches only the pages it needs. All of
these are generated at build time, so they always match the live docs.
Give your assistant one of these URLs when it needs the reference. Automatic
discovery depends on the assistant; publishing the files does not guarantee
that it will fetch them.
