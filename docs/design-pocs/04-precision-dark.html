Clone repositories, manage pull requests, and run pipelines without leaving your shell. Every command emits JSON — --json and --jq included — so it fits into scripts, CI, and agents.

Command reference

Sixteen command groups over the full Bitbucket Cloud 2.0 API, generated from a pinned OpenAPI spec.

bb repoClone, create, list, delete8 bb prFull pull-request lifecycle24 bb pipelineRun, watch, logs, stop7 bb issueTrack and update issues6 bb commitHistory and build status4 bb snippetCreate and share snippets4 bb workspaceWorkspaces you belong to2 bb projectProjects inside workspaces3 bb browseOpen the web UI1 bb apiRaw 2.0 endpoints, paginated1 bb authLogin, logout, whoami3 bb configManage local configuration3

Built for scripts, not just humans

Automation is a first-class output mode, not an afterthought bolted onto a text renderer.

  • Field projection. --json id,title,author.display_name returns a flat array — exactly the fields you asked for, nothing else.
  • In-process filtering. --jq '.[0].title' evaluates in-process. No jq binary, no shell pipe.
  • Stable exit codes. Machine-readable error codes documented per command.
  • Pagination. --paginate walks every page of any list endpoint.
ci.yaml — release job
$ bb pr list --json id,title --jq '.[0].title'
"feat: streaming pipeline logs"
 
$ bb api /repositories/acme/core-api/pullrequests --paginate --jq 'length'
47
 
$ bb status set abc1234 --key BB-DEPLOY --state SUCCESSFUL
✓ Build status published
