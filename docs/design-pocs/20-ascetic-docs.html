Pull requests

Twenty-four subcommands covering the full PR lifecycle — create, list, inspect, review, comment, and merge. Repository context is resolved from your git remote; -w and -r override it.

Subcommands

Usage

The shortest useful session. bb pr list resolves your workspace and repository from the origin remote and lists open PRs:

shellread-only
$bb pr list --state OPEN
#47 feat: streaming pipeline logs OPEN
#46 fix: retry on 429 rate limits OPEN
$bb pr view 47
Title feat: streaming pipeline logs
Branch feat/log-stream → main
Reviewers marek ✓ · 1 pending

Merging always names its strategy. There is no default — the flag is required, so no one ever merges with the wrong intent:

shellstate change
$bb pr merge 47 --strategy squash --close-branch
✓ Merged pull request #47 into main (squash)
✓ Deleted branch feat/log-stream
Repository context. Inside a git checkout, workspace and repository come from the origin remote. Explicit flags always win — bb pr list -w acme -r other-repo targets any repository you can access, from anywhere.

Scripting

Every subcommand supports --json with a field list, and --jq for in-process filtering — the same contract as the rest of the CLI. See JSON output for the full syntax.

shelljson output
$bb pr list --json id,title --jq '.[0].title'
"feat: streaming pipeline logs"
